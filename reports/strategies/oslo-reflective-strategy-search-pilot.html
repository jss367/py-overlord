October 14, 2026 · Prototype evaluation

Oslo: Reflective Strategy Search with Subscription Access

Subscription-backed reflection works.

The reflective-assisted recommendations won 197 of 300 fresh direct games against the genetic control (65.7%) across three search seeds. This is an exploratory result from a small search budget.

GEPA (Genetic-Pareto) uses a language model to reflect on execution feedback and evolve text configurations. Here it edits a validated JSON strategic plan, which the existing compiler turns into ordinary strategy rules. The reflection model runs through the Codex command-line interface (CLI) using the user's saved ChatGPT subscription sign-in. Gameplay requires no model calls or API credentials.

Fresh-game comparison

Each search seed trained both arms with the same opponents, genetic settings, and board-derived engine seeds. The assisted arm additionally received a GEPA proposal. Both recommendations were locked on validation games before their held-out games. Each recommendation played 100 games per opponent; the direct matchup used a separate set of 100 seat-balanced games for that seed. The direct matchup reused the first panel opponent's random seed block, so those two sets of outcomes should not be treated as independent. Later studies with a shared hard game allowance use a separate direct-matchup seed block.

What changed and what remains uncertain

GEPA produced a behaviorally new selected seed in 3 of three runs. Its editable decisions include opening targets, staged copy limits, build timing, dependencies, economy, scoring timing, and play order. The saved plans show the exact coordinated changes; the JSON evidence below includes both starting and proposed configurations. That establishes which decisions were expressible, not which individual edit caused an improvement.

This was a small pilot: 8 individuals, 2 genetic generations, 4 screening games per opponent, 20 validation/confirmation games per opponent, and at most 20 GEPA matchup evaluations per search seed. It is below the repository's published calibration budget. GEPA added compute; this is not an equal-compute comparison. A stronger study should use the full calibration budget, more search seeds and kingdoms, 400 or more fresh games per opponent, and a control with comparable total simulation resources.

The pilot's original schema 1 typed plan could not express every reference tactic, including a multi-Colony resource gate, custom Treasure conditions, or direct village/draw deck-count balancing. Reference strategies remain opponents and may use those custom policies. A later policy coverage audit extends schema 2 to reproduce both strong references; it does not change this historical pilot's results. The simulator uses victory points, then fewer turns, with a seat-order fallback for full ties; swapping seats balances that fallback. The largest final turn counter among held-out games was 57. Turn counts and scores are retained in the evidence.

Evidence and reproduction

A later five-seed comparison with shared hard game allowances uses the expanded policy space and a larger search. Its results are reported separately from this historical pilot.

Download the recorded study, per-game results, selection records and proposed plans. The experiment records its simulation-input fingerprint. Full request prompts and local checkpoints remain under .context/reflective-oslo-subscription-comparison/. Live model proposals are stochastic; rerunning the command can produce different plans even when simulator/search seeds are fixed.

The adapter requires a ChatGPT login, removes API credentials only in its child environment, disables shell, connector and web-search access, ignores custom CLI configuration, and runs in an empty read-only directory. A failed provider request fails the experiment. JSON decoding rejects unsupported plans before simulation. No account credentials are copied into the study artifacts.

Implementation: dominion/simulation/codex_reflection.py, dominion/simulation/reflective_strategy_search.py and scripts/reflective_evolve.py. See the official GEPA implementation, Codex non-interactive mode and subscription authentication for the underlying interfaces.
