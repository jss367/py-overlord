When to Retire a Strategy: Rebuild Comparison

September 17, 2026 · Repository simulator evidence and a proposed catalog policy

Keep runnable strategies for research and benchmarks; curate which ones are recommended. Rebuild Rush is a stronger head-to-head candidate than either Skulk Rebuild implementation in the tested setup. These results do not establish complete dominance or justify deleting the alternatives.

What the comparison establishes

Rebuild Rush references only Rebuild beyond the basic supply. Skulk Rebuild and Skulk Rebuild Improved reference Forager, Rebuild, and Skulk. The subset condition holds for their declared kingdom cards; none declares landscapes.

Rebuild Rush buys up to two Rebuilds; the other policies buy up to three and include Forager and Skulk purchases. These are comparisons of the existing implementations, not proof that every possible Skulk/Rebuild plan is inferior.

Both comparisons used the same fixed three-pile kingdom: Forager, Rebuild, and Skulk, plus the normal basic supply. Each player started with seven Coppers and three Estates. No landscapes, Shelters, Colonies, or cost modifiers were added. This is a minimal comparison supply, not a complete ten-pile kingdom.

Seeds 2026091700 through 2026091899 were each played twice, swapping the strategies’ seats. A tie means equal victory points and equal turns taken. The runner records ties explicitly instead of treating the battle helper’s seat-order fallback as a win. Games used the local simulator; different kingdoms, starting cards, opponents, or simulator changes may change the ranking.

Why head-to-head wins are not complete dominance

A strategy can beat another directly yet perform worse against a third opponent. Even a perfect sampled head-to-head record would not prove universal superiority. The useful replacement criterion is whether the simpler strategy is at least as effective against relevant opponents on the same supported boards and game settings, with some clear advantage.

The card subset establishes broader declared availability; it does not establish that performance criterion. No catalog-wide dominance audit or common-opponent comparison was performed here. The historical reason the stronger policy was missed was not investigated.

Recommended catalog policy

  • Retain implementations and stable links. Older policies remain useful as regression opponents, search seeds, and records of rejected ideas.
  • Mark candidates separately from confirmed replacements. These results support a “stronger tested alternative” link from both Skulk entries to Rebuild Rush.
  • Before hiding an entry from default recommendations, compare both policies against the same opponent panel on fixed compatible boards. Include relevant starting-card and landscape settings, both starting seats, fresh seeds, and uncertainty estimates. Require evidence that any performance loss is smaller than a stated practical tolerance; a nonsignificant difference alone is insufficient.
  • Record the scope of replacement. A “superseded on these tested boards” label should name the replacement, evidence, date, and settings. Preserve an option to browse all strategies.
  • Reserve deletion for duplicates or invalid implementations with no research value. A low leaderboard position or losing matchup alone is insufficient.

Both Skulk strategy pages now link to Rebuild Rush as a stronger tested alternative and to this evidence. The retirement policy remains a proposal; no strategies are hidden, removed, or certified as universally dominated.

Reproduce the comparison

From the repository root, run mkdir -p .context, then save the following as .context/check_rebuild.py and run PYTHONPATH=. python .context/check_rebuild.py. It prints both results and writes a JSON record under .context/.

Show the complete comparison script
import json
import random
from dominion.ai.genetic_ai import GeneticAI
from dominion.simulation.strategy_battle import StrategyBattle

class TieAwareBattle(StrategyBattle):
    def _select_winner(self, players):
        keys = [(p.get_victory_points(), -p.turns_taken) for p in players]
        self.tied = keys[0] == keys[1]
        return super()._select_winner(players)

battle = TieAwareBattle(log_frequency=0, log_folder='.context/rebuild-games')
kingdom = ['Forager', 'Rebuild', 'Skulk']
results = []
for opponent in ['SkulkRebuild', 'SkulkRebuildImproved']:
    counts = dict(wins=0, losses=0, ties=0)
    example_loss = None
    for i in range(400):
        seed = 2026091700 + i // 2
        random.seed(seed)
        a = GeneticAI(battle.strategy_loader.get_strategy('Rebuild Rush'))
        b = GeneticAI(battle.strategy_loader.get_strategy(opponent))
        seats = (a, b) if i % 2 == 0 else (b, a)
        winner, scores, _, turns = battle.run_game(*seats, kingdom)
        outcome = 'ties' if battle.tied else 'wins' if winner is a else 'losses'
        counts[outcome] += 1
        if outcome == 'losses' and example_loss is None:
            example_loss = dict(seed=seed, rebuild_rush_seat=1 if i % 2 == 0 else 2, scores={'Rebuild Rush': scores[a.name], opponent: scores[b.name]})
    row = dict(opponent=opponent, games=400, **counts, example_loss=example_loss)
    results.append(row)
    print(json.dumps(row), flush=True)
with open('.context/rebuild-comparison.json', 'w') as f:
    json.dump(dict(kingdom=kingdom, starting_cards='7 Copper, 3 Estate', seeds='2026091700..2026091899, each played in both seats', results=results), f, indent=2)
